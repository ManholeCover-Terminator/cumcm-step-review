# 编程手工作流程

## 一、读取输入

从 `PROJECT_ROOT` 读取题目附件、`题目分析报告.md` 和 `术语表格.md`。输入文件只读；输出写入新文件。

## 二、选择语言并动态检查依赖

根据用户要求、现有代码和模型函数选择 Python、MATLAB 或两者。只检查实际选中的功能。

Python：

```powershell
python "<SKILL_ROOT>/scripts/check_env.py" --features data visualization optimization
```

可选功能包括 `data`、`visualization`、`excel`、`optimization`、`integer-optimization`、`statistics`、`machine-learning`、`time-series`、`graph` 和 `image`。

MATLAB：

```matlab
addpath("<SKILL_ROOT>/scripts");
report = check_matlab_env(["data", "visualization", "optimization"]);
assert(report.ok, "缺少所选模型需要的 MATLAB 工具箱");
```

缺少依赖时报告精确名称，不自动改用另一个模型或语言。

## 三、实现与运行

1. 把数据读取、预处理、模型、验证、可视化和输出拆成清晰函数。
2. 随机算法显式设置种子。
3. 所有关键参数集中定义并写入复现清单。
4. 实际运行代码；禁止手写或伪造结果。
5. 检查约束可行性、数值范围、边界条件和验证指标。
6. 若模型本身矛盾，把实际报错和最小复现反馈给建模手。

## 四、P1 最小可运行结果

完成数据读取、预处理和核心求解纵向切片后，在全量运行与正式出图前派发独立质检 Subagent：

1. 从 `PROJECT_ROOT` 执行一条最小命令。
2. 每个会驱动后续全量计算的模型族至少覆盖一个真实输入或结构等价小实例。
3. 核对退出码、输入到结果的追溯、单位、数值范围、关键约束和 `M1` 模型合同。
4. 实现问题返回编程手；公式、约束或参数合同问题携命令、堆栈和预期—实际证据返回建模手。

`P1` 未返回 `PASS` 不得继续全量计算、参数扫描和正式出图。它不要求三类图、完整敏感性分析或最终性能。
逐题模式下，`P1-qN` 只针对当前题的最小命令切片；下一题开始前必须先通过前题的 `P2-qN`。

## 五、可视化执行链

1. 核对数据的行列数、表头、类型、缺失、分组样本量、分布、异常值、单位与处理记录；先用 `profile_data.py` 生成剖析报告（解读见 `数据剖析解读.md`），类型识别错误先修正再重跑。
2. 按 `期刊规范.md` 确认目标竞赛/期刊的栏宽、字号、字体与 DPI，官方模板优先；Python 侧可用 `apply_publication_style(..., journal=..., serif_for_zh=...)` 套用预设。
3. 从题目分析报告列出全部子问题并规范为 `q1…qN`；为每张候选图明确对应子问题、核心结论、所属类别、证据映射、统计口径和最终尺寸；需要选图时加载 `图表选择与避坑.md`。
4. 从 `<SKILL_ROOT>/scripts/` 复制 Python 或 MATLAB 出版样式工具到 `PROJECT_ROOT/utils/`，再由项目代码调用。
5. 按 `raw_q1_*`、`process_q1_*`、`result_q1_*` 等命名生成三类图，每类至少 3 张逻辑候选图、合计至少 9 张，且每个子问题在三类中各至少 1 张；默认每张只导出 300 DPI PNG，不设上限，需要矢量时再追加 SVG。
6. 正式导出前按 `视觉回审.md` 完成自检闭环：`render_preview` 渲染预览、`audit_layout` 程序自检、实际打开预览按 8 项清单读图；发现问题改代码重跑。
7. 运行 `python "<SKILL_ROOT>/scripts/figure_audit.py" "<PROJECT_ROOT>/figures" --questions q1 q2 ... qN --strict`，并实际打开 PNG 与灰度预览进行视觉检查；发现问题回到源代码修正并重新运行。
8. 逐题模式下，按 `q1…qN` 逐题执行步骤 3–7：每题的审计命令只传当前题（`--questions qN`）；全部题目完成后运行整题审计 `--questions q1 q2 ... qN --strict`，作为 `P2-总` 的证据输入。

## 六、文件结构

```text
PROJECT_ROOT/
├── data/                         # 输入，只读
├── 题目分析报告.md               # 建模手产物，只读
├── 术语表格.md                   # 建模手产物，只读
├── 问题1_求解.py 或 问题1_求解.m
├── results/
│   ├── 问题1_结果.csv
│   ├── 题目指定结果.xlsx         # 仅题目要求或需保留模板时
│   └── 复现清单.json
└── figures/
    ├── raw_q1_*.png                       # 问题一原始数据图（默认 PNG）
    ├── process_q1_*.png                   # 问题一模型运行过程图
    ├── result_q1_*.png                    # 问题一最终结果图
    ├── raw_q2_* / process_q2_* / result_q2_*  # 其余问题依次覆盖
    └── 图表面板.html
```

同一图的多格式输出（PNG/SVG/灰度预览）按 1 张逻辑图计数。图可以继续多生成候选版本；每张图仍须数据正确、坐标含义清楚，面板内默认不放标题和编号。

## 七、Excel

- 普通结果表优先 CSV。
- 题目要求 `.xlsx`、多工作表、公式或既有模板时使用 Excel。
- 读取 XLSX 时显式声明是否有表头；第一行就是数据时使用 `pandas.read_excel(..., header=None)` 或 `read_excel_rows(..., header=False)`，并核对首行、末行与预期行数。
- 模板结构和公式不随意修改，另存到 `PROJECT_ROOT/results/`。
- 公式工作簿使用 `<SKILL_ROOT>/tools/xlsx/scripts/recalc.py` 重算；失败或超时时原文件不应被覆盖。

## 八、复现清单

示例：

```powershell
python "<SKILL_ROOT>/scripts/repro_manifest.py" `
  --project-root "<PROJECT_ROOT>" `
  --input "<PROJECT_ROOT>/data/input.csv" `
  --seed 42 `
  --parameters '{"alpha":0.1,"max_iter":1000}' `
  --command "python 问题1_求解.py --seed 42" `
  --package numpy --package scipy
```

唯一复现命令必须从 `PROJECT_ROOT` 可直接执行，并生成与论文引用一致的表格和图。

## 九、P2 编程终检

代码、结果表、每类至少 3 张且覆盖全部子问题的三类图和复现清单完成作者自检并冻结后，按 `<SKILL_ROOT>/references/Subagent调度.md` 派发独立质检 Subagent。质检者重跑唯一复现命令，核对哈希、环境、种子、参数、关键数值、约束、边界、量纲、统计计算和各子问题图表语义；带全部 `--questions` 的 `figure_audit.py --strict` 结果和实际 PNG/灰度预览作为证据输入。`P2` 未返回 `PASS` 不得进入论文阶段。
逐题模式下，每题冻结后先执行 `P2-qN`（只核对当前题代码、结果与图）；全部题目完成后追加 `P2-总`：重跑各题唯一复现命令，带全部 `--questions` 运行 `figure_audit.py --strict`，核对全题图表覆盖、复现清单完整性与跨题一致性。复现清单在全部题目完成后统一生成。
