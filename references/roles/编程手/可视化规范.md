# 可视化规范

本规范把 Nature Skills 的“图是可审查的视觉论证”和 SciPilot 的“先理解数据、再选图、最后回看成图”融入数学建模流程。默认采用克制、清晰、可编辑的 Nature/SCI 风格基线，但这不代表通过任何期刊的官方格式认证；目标竞赛、学校或期刊的当届规范始终优先。

配套工具：数据剖析 `scripts/profile_data.py`、期刊尺寸 `期刊规范.md`、
视觉回审闭环 `视觉回审.md`。

## 三类图与候选策略

1. 原始数据图：分布、时间趋势、空间结构、相关性和异常点。
2. 模型运行过程图：收敛、训练、残差、灵敏度、消融和约束状态。
3. 模型最终结果图：方案、预测、排名、误差和不确定性。

三类都要覆盖，并先把题目全部子问题规范为 `q1…qN`。文件名使用 `raw_q1_*`、`process_q1_*`、`result_q1_*` 等格式；每类至少生成 3 张逻辑候选图、合计至少 9 张，同时每个子问题在三类中各至少 1 张。同一图的多格式输出（默认 PNG、可选 SVG/灰度预览）按 1 张计数，不设置最多图数。共享同一基础数据时，也要围绕各子问题的目标生成不同分析视角，禁止复制同一张图或只替换标题凑覆盖。最终进入论文的每张图仍须说明它支撑的子问题与结论。

## Nature/SCI 视觉论证流程

Nature/SCI 风格不是“换一套颜色”，而是让图形成可快速阅读、可复核的证据链。每张候选图按以下顺序设计：

1. **一句话结论**：先写希望读者看出的关系、差异或决策，不以“展示某某结果”代替结论。
2. **选择叙事原型**：在单面板定量图、同尺度定量网格、主图 + 辅助证据、示意图主导、图像 + 定量结果中选择一种；不要默认套等宽双子图。
3. **确定视觉层级**：指定主面板和辅助面板。信息量、重要性或纵横比不同时，用 `width_ratios`/`height_ratios` 分配空间；只有证据权重和尺度相近时才等分。
4. **选择视觉编码**：连续、离散、时间、分布、矩阵和空间变量使用与语义一致的图型；同时决定是否需要原始点、区间、基线、直接标注或共享图例。
5. **按最终尺寸绘制**：先确定论文中的物理尺寸，再设置字体、线宽、标记和面板间距；禁止依赖 Word/LaTeX 大幅缩放补救。
6. **三层复核**：先检查统计与图型语义，再通过自动门禁检查明显设计错误，最后实际打开彩色图和灰度图，在预计尺寸下回看；最多连续微调三轮，仍不清楚时应重选图型或布局。

候选图数量不受限制，但单张图应围绕一个核心结论组织。不能因为“图多多益善”就把互不支撑的结果塞进同一画布；应该多生成独立候选图，交由用户和论文手选择。

## 绘图前门禁

### 1. 数据剖析

先核对实际读取结果，再决定图型：

- 运行 `python "<SKILL_ROOT>/scripts/profile_data.py" "<PROJECT_ROOT>/数据文件" --group ...` 生成剖析报告；报告解读见 `数据剖析解读.md`。
- 文件、工作表、表头约定、首行、末行和总行数；
- 每列的数据类型、单位、缺失率、唯一值和数值范围；
- 各分组样本量、分布形态、异常值与重复测量结构；
- 变量相关性、时间/空间顺序和模型输出的统计定义；
- 任何删行、聚合、抽样或异常值处理的前后数量、规则与理由。

不得为了套模板或加快绘图静默删数据。点数过多时可使用透明度、hexbin、密度图或有明确规则的聚合，并保留原始数据图。

### 2. 图表契约

写代码前，在工作记录或代码注释中明确：

```text
核心结论：这张候选图希望读者看出什么？
所属类别与子问题：raw_q1 / process_q1 / result_q1 等
叙事原型：单面板 / 同尺度网格 / 主图+辅助证据 / 示意图主导 / 图像+定量结果
证据映射：每个面板分别使用什么数据、回答什么问题？哪个是主面板？
布局比例：为什么等分，或为什么使用当前 width_ratios / height_ratios？
图型与理由：为什么这种视觉编码适合当前变量和结论？
统计要求：n、中心统计量、离散程度/区间、检验与校正是什么？
标注策略：直接标注、共享图例还是图外图例？为什么？
输出要求：最终宽高、语言、默认 PNG（可选 SVG）、目标模板中的预计尺寸是什么？
风险检查：是否可能误导尺度、遮挡数据、缺字或混淆颜色？
源数据追溯：输入文件、工作表/字段、过滤或聚合前后数量是什么？
```

信息不足时先从题目分析报告和数据推断，明确记录假设；会改变结论或统计口径时再询问用户。无法判断图型时读取 [图表选择与避坑.md](图表选择与避坑.md)。

## 出版级样式基线

- 默认白色背景、无网格线、无装饰性渐变和立体效果；普通数据图隐藏上、右边框。
- 图宽按论文中的最终尺寸设置，避免在 Word/LaTeX 中大幅二次缩放。内置 `report` 宽度为 6.3 in，`single`/`double` 仅作为常见单栏/双栏起点；官方模板有规定时覆盖它们。
- 目标期刊或竞赛有明确栏宽、字号、字体要求时按 `期刊规范.md` 执行；
  Python 侧可用 `apply_publication_style(language="zh", width="double", journal="nature")`
  一键套用期刊预设（nature/science/cell/ieee/general/okabe-ito/wong，可用 `variant=` 选变体），
  中文期刊混排传 `serif_for_zh=True`。
- 字号按最终印刷尺寸设定：正文标签 8.5–11pt（按图宽 3.5–7.2 in 线性插值），刻度与图例 ≥7.5pt；任何关键字号都不停留在 10pt 默认整图缩放，避免图大字小和 AI 默认痕迹。面板内默认不放标题，完整结论和解释移到图注。同一组图的字体、字号和线宽保持一致。
- 图型多样性：同一类型图（折线/柱状/散点/热力图/箱线等）全篇不宜超过 3 张，同类图不连续出现 3 张以上；同一子问题多张图尽量混排不同图型，避免审美疲劳。
- 同一方法、变量或方案跨图保持相同颜色语义。优先使用色觉友好配色，并以线型、标记或纹理提供冗余编码。
- 饱和色只突出核心系列或关键阈值，次要系列使用灰色或低饱和度颜色。纹理仅用于确有灰度区分需求的少量类别，不能把密集斜线当装饰。
- 连续单向数值使用感知均匀色图，如 `viridis`、`magma`、`cividis`；以零为中心的正负数据使用带明确中心值的发散色图。禁止 `rainbow`、`jet` 等会制造虚假视觉梯度的色图。
- 坐标轴必须写变量名和单位；连续颜色映射必须有带单位的 colorbar。柱状图通常从零开始；需要截断或对数轴时必须有统计/物理理由并显式标注。
- 三条以内的关键曲线优先在线尾直接标注；四至五项可使用一个共享图外图例；超过五项时优先拆分、分面或突出核心系列。图例不得遮挡数据，多面板图不得为相同语义重复放置图例。
- 稠密曲线不得在每个采样点放标记；标记只用于观测位置、抽样位置或需要区分类别的稀疏位置，使用 `markevery` 控制密度。
- 多面板图共享颜色语义和可比较尺度；默认不放面板编号，确需编号时统一使用 `a`、`b`……小写粗体，位于左上角且不遮挡数据。
- 误差棒、阴影区间和箱线图必须在图注说明样本量、中心统计量、SD/SEM/CI/IQR、检验方法及多重比较校正。
- 统计量、置信区间和 p 值必须由代码从当前数据计算，禁止硬编码；置信区间不能用标准差冒充。
- 数据图默认只输出一个至少 300 DPI 的 PNG，不要只调用 `show()`，也不要用截图或 JPEG 代替正式导出；需要矢量或色盲检查时再追加 SVG 或灰度预览。

## 复用现有代码或模板

- 先判断是完整复用、结构复用、仅继承样式，还是应该重新实现；不能因为示例能运行就认定适配当前数据。
- 写清“模板字段 → 当前字段 → 统计角色 → 单位”的映射，不得静默选择方便的列或改变类别顺序。
- 对数、比值、归一化、开方、分箱、相关性、PCA 和聚类都要重新检查输入条件；条件不满足时不能只为画出相似图而修改统计含义。
- 默认使用全部有效观测。确需过滤、聚合或抽样时，记录规则、前后数量、随机种子及其对结论的影响。
- 示例数据和模拟数据不得混入正式结果；先把模板复制到 `PROJECT_ROOT` 再修改，保持 `SKILL_ROOT` 只读。

```python
import matplotlib.pyplot as plt
from utils.plot_style import (
    PALETTE,
    add_panel_labels,
    apply_publication_style,
    export_figure,
    publication_subplots,
)

apply_publication_style(language="zh", width="report")
fig, axes = publication_subplots(
    1, 2, width="report", aspect=0.56, width_ratios=[1.45, 1]
)
axes[0].plot(x, raw_values, color=PALETTE["primary"])
axes[0].set(xlabel="时间（s）", ylabel="观测值（单位）")
axes[1].plot(x, predicted, color=PALETTE["contrast"], label="预测")

    x, lower_ci, upper_ci,
    color=PALETTE["contrast"], alpha=0.16, label="95% CI",
)
axes[1].set(xlabel="时间（s）", ylabel="预测值（单位）")
axes[1].legend()
# add_panel_labels(axes)  # 保留但默认不使用：图内不画面板编号，确需时取消注释
export_figure(fig, PROJECT_ROOT / "figures" / "result_q1_prediction")

```

`publication_subplots()` 把最终尺寸和主次面板比例写进代码。`export_figure()` 默认检查缺字、画布外文字、刻度重叠，以及长标题、超量图例、密集逐点标记、非零基线柱状图和冗余小矩阵 colorbar，再按固定物理尺寸导出 PNG（灰度预览仅在需要时写入 `figures/_qa/`）。除非官方模板有明确冲突且已记录理由，不得设置 `strict_design=False`；不要使用 `bbox_inches="tight"` 代替布局修复，它会改变图表契约中的最终宽高。

## 导出后的自检闭环

1. 运行项目代码，生成默认 PNG（需要时追加 SVG 或灰度预览）。
2. 正式导出前按 `视觉回审.md` 完成一轮预览自检：`render_preview()` 渲染、
   `audit_layout()` 程序自检、实际打开预览按 8 项清单读图；发现问题改代码重跑。
3. 用内置审计器检查三类前缀、每类至少 3 张逻辑候选图、全部子问题三类覆盖、PNG DPI 和实际物理尺寸元数据；SVG 存在时检查其可编辑文本（提示级）。`--questions` 必须列出题目全部子问题：

   ```powershell
   python "<SKILL_ROOT>/scripts/figure_audit.py" "<PROJECT_ROOT>/figures" --questions q1 q2 q3 --strict
   ```

4. 实际打开每张 PNG（存在灰度预览时一并打开 `_qa/*_grayscale.png`），在论文预计显示尺寸下逐项检查：中文、负号、希腊字母是否缺字；坐标是否裁切；刻度、标注和图例是否重叠；颜色与灰度是否可区分；数据点、误差棒和边界是否被坐标范围截断；多面板间距和跨图语义是否一致。
5. 用一句话复述成图的第一视觉结论；若它不是图表契约中的核心结论，或第一眼只看到大标题、大片纹理、图例和空白，则视为失败。检查主面板是否确实最突出，辅助面板是否提供独立证据，而不是机械等分画布。
6. 发现问题必须回到绘图代码修正，重新运行、重新审计并再次打开预览；不得直接在 PNG 上涂改。
7. 自动审计只能拦截一部分高风险设计，不能代替对数据、统计含义和最终视觉效果的检查。
