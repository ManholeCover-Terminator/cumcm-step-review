> 本文件原为独立技能 `cumcm-abstract-writing`，现内嵌于 `cumcm-step-review`，**不再作为独立技能被发现**；由主 Skill 在"写/改/评摘要"时按强制执行协议与渐进式加载表读取。方法论基于 93 篇国赛优秀摘要语料（`摘要汇总.md`）提炼，覆盖写作原则、标准结构、"起草 → 二次验证 → 定稿"两阶段闭环、评审视角、句式模板、常见误区与自检清单。

- **[templates.md](templates.md)** —— 句式模板：12 类句子级模板 + T1~T8 段落级改写技巧（回答"这句/这段怎么写"）；

- **[example.md](example.md)** —— **8 个真实改写教学案例**（中等→国一→中强全覆盖，回答"实例长什么样"）。

## 一、写作原则（先记住这 9 条）

1. **摘要必须自成体系、可独立阅读。** 评审可能只看摘要。把问题、方法、结果、结论讲完整，不依赖正文解释。总起段=题目的一句话转述，逐题段=每问的完整闭环。
2. **严格跟随赛题问题结构。** 赛题分几问，摘要就分几段，用"针对问题一/二/三/四"做显式锚点，让评审一眼对应到题目要求。绝不打乱顺序、合并或漏掉某问。
3. **每问必须落到量化结果。** "建立模型"之后必须给出具体数字：`最大输出功率为 229.6819W，最优直线阻尼系数为 37639`。没有数值的摘要等于没做。
4. **模型名称必须具体，不写泛泛的方法。** 写"基于优势矩阵的等级划分模型"，不写"建了个模型"；写"K-means 聚类"，不写"聚类"。术语的精确度 = 工作的落地度。
5. **突出创新点，且有证据。** 至少留 1~2 句专门讲"本文哪里不同"，紧跟对比数据或验证结果（"预测准确率 96.75%，较传统决策树提升 15.36%"）。
6. **语言精炼、可检验。** 主动句为主，删废词；形容词只用"准确/合理/显著/稳定/最优"等可检验判定词，禁"大概/很好/非常不错"这类无量化支撑的词。
7. **结果可验证、与正文一致。** 摘要里的每个方法名、数值、表号都必须在正文有对应；正文的创新点摘要必须点出。
8. **事实保真（改写模式）。** 改写/润色既有摘要时，绝不改变原文的数值、结果、结论、模型名与表号，只优化表达、结构与重点；正文与摘要都没有的验证/灵敏度证据一律不新增——用已有的等价证据替代（求解器 OPTIMAL、与基线对比、正文验证段）。**改写=优化表达，不是重写事实。**
9. **摘要不放公式（公式清零）。** 93 篇优秀语料零显示公式、零整式——模型公式一律文字点名（"推导了……反射率公式"），参数符号与数值（R₀₁≈0.19、Δν、Qₘᵦ=0.35）作行内记号保留为结果载体，公式本体下沉正文。（参照 T1／清单 D6／误区 M16）

## 二、标准结构模板（三段式骨架）

```
【总起段 · 1 段】
  开头范式三选一：
  A. 背景意义型：一句背景/意义 → 一句"本文针对……问题，……" → 一句方法路线（**背景句须放最前，顺序固定为 背景→问题→方法**，不可把背景句甩到段末）
  B. 方法直入型：一句"本文针对/研究了……问题" → 一句方法路线（用什么理论/建什么模型）
  C. 问题引入型：一句"本题要求我们……" → 一句研究边界与整体目标
  末句给出整体策略/总目标（可选：总结果）。

【逐题段 · N 段（一段一问）】
  每段按 4 拍闭环：
  ① 问题：一两句转述该问要求（不照抄原题）
  ② 方法：先"首先/接着/然后/最后"讲建模思路 + 算法
  ③ 结果：给关键数值（带单位与合理精度）
  ④ 结论：判定/解释（更优/可信/合理/验证了……）
  段与段之间用"在问题二模型的基础上"式接力，体现递进。

【收束段 · 可选，1~3 句】
  "综上所述"回扣全题 → 一句创新/亮点 → 一句评价/推广（具有较好的实用性、可推广至……）。

【关键词 · 1 行】
 "关键词：对象类词，方法类词，算法类词"（4~6 个，与正文术语完全一致）。
```

篇幅控制：约 400~800 字，随子问题数伸缩（1~2 问压到 300~500，5 问可到 1000）；**高密度摘要**（每问都带数值+验证证据，如三问 ~1100 字）可放宽，以信息密度为准，不为压字数删事实。

## 三、单一大流程：起草 → 二次验证 → 定稿（两阶段闭环）

「从赛题起草」与「改写/评审既有摘要」不再是二选一的两条路，而是**同一条大路线的两个阶段**，串联成闭环。核心思想：**写完后，把初稿当成"要挑错的别人的稿子"，切换评审者视角再复核一遍。**

```
【输入判断 · 只影响从哪进】
   只有赛题、没有现成摘要 ──────────────▶ Stage 1 起草（第四节，8 步）
   已有摘要或全文（Word/PDF/图片转文字）▶ 直接进入 Stage 2（第五节）
                                              │
                        Stage 1 起草 ──产出初稿（草稿，非定稿）
                                              ▼
                        Stage 2 二次验证（评审/改写）
                            一验质量：评审 30 秒阅读路径逐条查
                            二验事实：数值/模型名/结论/表号回正文逐项比对
                                              ▼
                              定稿 + 验证报告（第五节输出契约）
```

- **Stage 1 · 起草**（原路径 A，见**第四节**）：从赛题拆问、定总起、逐题起草，产出**初稿**。
- **Stage 2 · 二次验证**（原路径 B 完整流程 B1~B6，见**第五节**）：把初稿（或用户拿来的既有摘要）当"待评审稿件"，走一遍「诊断 → 事实盘点 → 改写 → 事实核验 → 自检」。**一验质量**（结构、逐问对应、数值、方法、创新、验证）；**二验事实**（起草模式下尤其要防止初稿里的数字是"想出来/编出来"的，每个数值都应有正文出处）。
- 两种入口**共用同一输出契约**（第五节）：① 验证/诊断报告 ② 定稿全文 ③ 关键改动说明 ④ 事实核验表。

改写/评审既有摘要时，「事实保真」（原则 8）仍是硬约束：正文没有的证据不得虚构。

## 四、Stage 1 · 起草：从赛题起草（8 步）

> 本阶段产出**初稿（草稿，非定稿）**：先保证逐问完整、骨架正确，不做正式自检与润色——那是 Stage 2 二次验证（第五节）的职责。初稿写完后必须进入 Stage 2。

1. **读题拆问**：把赛题拆成子问题，列出每个子问题的"要什么、给什么"。摘要的结构就由子问题数决定。
2. **定总起段**：选开头范式（背景/方法/问题引入），一句话讲清"本文针对什么问题、用什么路线"。
3. **列逐题提纲**：每问写下"方法名 + 关键结果数字 + 结论判定词"三个要点，先搭骨架。
4. **逐题起草**：按"问题→方法→结果→结论"四拍写每段，先保证完整，再压缩。
5. **补数据与验证**：每段检查是否含具体数值；把误差/拟合度/灵敏度/对比验证写进去。
6. **提炼创新点**：找出全文最出彩的 1~2 点，写"本文的亮点在于/特色在于/创新性在于……"，并配证据。
7. **收束与关键词**：写"综上所述"段；提炼 4~6 个与正文一致的关键词。
8. **初稿通读**：通读一遍，保证逐问完整不缺、骨架连贯即可。**正式自检与润色交给 Stage 2 二次验证**（第五节 B2 诊断、B4 改写、B6 自检），不要在起草阶段反复打磨。

---

## 五、Stage 2 · 二次验证：评审/改写既有摘要（B1~B6）

> 本阶段是**统一收口**：输入可以是 ①Stage 1 的初稿，也可以是 ②用户直接拿来的既有摘要；无论哪种，都当**待评审稿件**处理，走一遍「诊断 → 事实盘点 → 改写 → 事实核验 → 自检」。「事实保真」（原则 8）与 **G 组自检**（第九节）在两种入口下都生效，起草与改写**共用下文输出契约**。

1. **B1 提取原摘要**：从文档/PDF 中定位摘要区并转成文字（注意公式、表格可能丢失，需对照原文补全）。**起草模式（从 Stage 1 进入）跳过本步**，输入即初稿。
2. **B2 诊断**：对照 `checklist.md` 与 `mistakes.md` 逐条过，列出问题点并编号（标注对应原则/误区/清单条目）。**先按第六节"评审 30 秒阅读路径"扫描**（结构扫描→逐问找结果→找模型名→找创新→找验证），再逐条过清单。**提示**：若原摘要结构、结果已达标（强摘要），问题多集中在错别字、术语混用、标点与编号统一（C9/E4/E5），诊断时优先扫这几项，其中**全/半角标点混用**是跨案例高频问题（C9/E4），**公式残留（D6/T1，93 篇语料零公式）**必查；若为**中强摘要**（结构完整但可优化），除上述外还应检查总起段结构（范式 A/B/C）、是否缺收束段（A7）、关键词是否超限（E3）、**结果句是否缺数值**（仅定性结论时回正文结果表补入）。
3. **B3 事实盘点**：先列出稿件**全部关键事实**——数值+单位、模型名、结论判定、表号/附录，逐项保留（原则 8）。**起草模式下另有要求**：初稿里每个数值都应在正文/计算过程有出处；暂时找不到出处的，在盘点表里标记"待确认"。
4. **B4 改写**：按第二节结构模板重构表达；用 `templates.md` 的段落级技巧（T1~T8）公式清零（T1，模型公式文字点名）、去重复衔接、补对比基准、统一句读、删弱填充句。**逐问核对结果句有无数值**：若某问只有定性结论（如"需要/不需要""更优"），回正文结果表/计算段提取临界值补入（原则 3／清单 A5，定位方法见清单 A5）。
5. **B5 事实核验**：新稿每个数值/模型名/结论与原稿和正文**逐项比对**，确认未变；未新增正文没有的证据；并核验**算法/方法名的适用问号范围**与正文逐问对应（如"全程采用 CP-SAT"须确认问题一是否也用——局部方法不得放大到全文，M14）。**起草模式的核验含义**：初稿的数值回正文/实际计算结果逐项比对，防止数字是"想出来/编出来"的；找不到出处的数字标出并**询问确认，不臆造**。
6. **B6 自检并输出**：按 `checklist.md` 过一遍（**两种入口都须过 G 组事实保真**：数值有出处、未新增无依据证据），按下述输出契约交付。

### 统一输出契约（起草与改写共用）

- **① 验证/诊断报告**：列出问题点，标注对应原则/误区/清单编号。
- **② 定稿全文**：完整摘要。
- **③ 关键改动说明**：每处改动对应"原则 N / 模板 Tn / 清单 X"。
- **④（可选）事实核验表**：原值 → 新值对照（起草模式：初稿值 → 正文出处值），证明关键事实未变/有出处。

完整教学案例见 [example.md](example.md)。

## 六、评审评分视角（精炼）

**此视角即 Stage 2 二次验证"一验质量"的依据**（第五节 B2）：起草完成后，借它把自己的初稿当评审稿自评一遍。

评审约 30 秒读摘要的路径：**结构扫描 → 逐问找结果 → 找模型名 → 找创新 → 找验证**。五个得分点：问题对应性、结果完整性、方法具体性、创新突出性、表达清晰度。

**自评用法**：先修"0 分项"（缺结果、缺对应、方法笼统，对应 ▲ 必查）→ 再修"半衰项"（创新被淹没、验证单薄，常是奖项档位瓶颈）→ 最后修"衰减项"（衔接重复、篇幅、术语一致性）。

详见 [analysis.md](analysis.md) 维度九。

## 七、句式模板（精炼版）

写句子时参考 [templates.md](templates.md)（完整模板库，含**段落级改写技巧 T1~T8**）。最常用的几组：

**段落级改写常用**：T1 摘要不放公式（公式文字点名、下沉正文）／ T2 去重复衔接 ／ T3 补对比基准 ／ T8 长枚举取舍（视题设要求而定，交付序列必保留）。

- **总起**：`本文针对……问题，基于/结合/以……为基础，建立了……模型。`｜`本文研究了……，首先……，进而……，实现了……。`
- **问题复述**：`针对问题一，题目要求……，本文首先……`
- **方法**：`通过……，建立……模型`｜`采用……算法对……进行求解`｜`考虑到……，本文对……作了……改进`
- **结果**：`求得/得到/计算出……为……`｜`结果表明，……`｜`较传统……提升/降低……`
- **结论**：`得到……的结论`｜`验证了模型的准确性/合理性`｜`说明……更优/更可信`
- **收束**：`综上所述，本文……`｜`本文……具有较好的实用性和可推广性`

## 八、常见误区（精炼版）

完整误区和逐条修正见 [mistakes.md](mistakes.md)（M1~M16）。**最高频的 5 个**：

1. **只写过程不写结果**（每问没有数值）。
2. **方法笼统**（"建立了一个模型""用了数学方法"）。
3. **照抄题目**，没有自己的转述和建模动作。
4. **各问之间无衔接**，像散装串珠。
5. **篇幅失控**（过长堆砌背景 / 过短缺结果）。

改写任务另注意 **M14 改写时事实失真**（改了数值、新增正文没有的结论）与 **M16 摘要放具体公式**（93 篇语料零公式，模型公式一律文字点名）。

## 九、自检清单（精炼版）

成稿后逐项打勾，完整版见 [checklist.md](checklist.md)。**硬性门槛：全部 ▲ 必查项必须 ✔**；改写任务须另过 **G 组事实保真**：

- [ ] ▲ 摘要可独立读懂全部问题的方法与结果？
- [ ] ▲ 逐题段与赛题子问题一一对应，顺序一致？
- [ ] ▲ 每问都有量化结果（数值+单位）？
- [ ] ▲ 模型名具体、术语与正文一致？
- [ ] ▲ 有验证（误差/拟合度/灵敏度/对比/求解器最优状态）？
- [ ] ▲ 无模糊词、无废句、无照抄原题？
- [ ] ▲ 篇幅在合理区间？关键词 4~6 个且与正文一致？
- [ ] ▲ 摘要不放公式（模型公式一律文字点名，参数/数值行内记号保留）？
- [ ] （改写模式）G1~G3：数值/模型名/表号与原稿一致，未新增正文没有的证据。
- [ ] （改写模式）G7：算法/方法名的适用问号范围与正文逐问核验，局部方法不得放大到全文（M14）。
- [ ] （改写模式·强摘要）若结构、结果已达标，重点自查**错别字、术语混用、标点与编号统一**（C9/E4/E5）——这是强摘要改写的主战场。
- [ ] （改写模式·中强摘要）若结构完整但可优化，另查**总起段结构、收束段缺失、关键词超限、结果句缺数值**（缺数值时回正文结果表补入）。

## 十、引用语料出处编号说明

`references/` 各文件中出现的 `#N-题号` 指 `摘要汇总.md` 中「**N. 题号**」标题对应的那篇（如 `#43-2020C109` 指第 43 篇 2020C109）。写作时可打开 `摘要汇总.md` 对照该篇完整摘要，体会结构、动词、数据密度与收束方式。改写实例可对照 [example.md](example.md) 的教学案例。
