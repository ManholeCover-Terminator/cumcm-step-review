# 摘要自检清单（写完后逐项对照）

> 使用方式：成稿后逐项打勾。任何一项打 ✗，按「修正动作」处理（误区对应编号见 [mistakes.md](mistakes.md)，句式参考 [templates.md](templates.md)，道理依据见 [analysis.md](analysis.md)）。
> 三档判定：✔ 通过 ／ ▲ 部分满足（需改） ／ ✗ 不通过（必改）。
> **优先级**：▲ 必查（不通过即不合格，21 项）／ ○ 应查（应尽量通过，18 项）／ ◇ 建议（锦上添花，7 项）。
> **改写模式**：若任务是"改写/评审既有摘要"，除 A~F 外还必须逐项过 **G 改写模式专用**（事实保真）。

---

## A. 内容完整性（A1~A7）

- [ ] **A1** ▲ 摘要可独立读懂：仅读摘要，评审就能知道题目解决的所有子问题的**方法**与**结果**。（✗ → 参照 M1）
- [ ] **A2** ▲ 总起段交代了「研究问题 + 方法路线」（三选一开头范式：背景意义/方法直入/问题引入）。
- [ ] **A3** ▲ 逐题段与赛题子问题**一一对应**，且顺序与赛题一致，无漏问、无合并。（✗ → 参照 M3）
- [ ] **A4** ○ 每个逐题段内部都含「问题→方法→结果→结论」四拍闭环。
- [ ] **A5** ▲ 每问都有**量化结果**（数值 + 单位），不是只有过程描述；**仅定性结论（需要/不需要/更优）不算量化**，缺数值时回正文结果表提取临界值补入。**回正文定位方法**：按关键词/表号（如"5.2.2 结果表"）搜正文 → 定位结果表/计算段 → 核对单位与精度后原样摘录。（✗ → 参照 M1）
- [ ] **A6** ▲ 有验证证据：至少 1~2 处（R²/误差/与实测对比/灵敏度/算法互验/求解器最优状态）。（✗ → 参照 M10）
- [ ] **A7** ○ 有收束：或"综上所述"总结，或"亮点/特色"句，或"可推广至……"。（✗ → 参照 M8）

## B. 逻辑链条（B1~B7）

- [ ] **B1** ▲ 全文逻辑主线 = 背景→问题→方法→结果→结论，总起段预告、逐题段闭环、收束段回扣。
- [ ] **B2** ▲ 各逐题段之间有**接力关系**（"基于问题 N 的模型""在此基础上""推广至"）。（✗ → 参照 M4）
- [ ] **B3** ○ 因果显式：每处"由于/考虑到/因为"之后紧跟"因此/故/于是"的对策。（✗ → 参照 M9）
- [ ] **B4** ○ 方法流程用"首先→接着/然后→最后"组织，内部次序清晰。
- [ ] **B5** ○ 每段"结果表明/求得"之后必有具体的"结论/判定"，不停留在数值罗列。
- [ ] **B6** ◇ 从简到繁/从特殊到一般/从结果反推等递进手法至少体现一种。
- [ ] **B7** ○ 模型改进与取舍有理由（"正面求解困难，于是离散化"式），不是拍脑袋换方法。

## C. 语言表达（C1~C9）

- [ ] **C1** ○ 主动语态为主；"本文/我们"全篇统一，不混用。
- [ ] **C2** ▲ 无模糊词：无"大概/大约/较好/不错/非常多"等无量化支撑的评价；**删模糊词时同步保留其后的证据句**（"定位结果非常准确，误差均小于 1×10⁻¹²"→删"非常准确"，保留"误差的绝对值均小于 1×10⁻¹²"）。（✗ → 参照 M2/M6）
- [ ] **C3** ○ 无废句、无纯过渡废话；信息密度高；无语义绕句（每句读一遍能立即说出"谁做了什么、结论是什么"）。（语义绕句 → 参照 M15）
- [ ] **C4** ▲ 术语精确到算法/模型全名（K-means 聚类、遗传算法、灰预测 GM(1,1)…）。（✗ → 参照 M2）
- [ ] **C5** ▲ 摘要中每个方法名/模型名在**正文有对应**，不出现"摘要独有"的方法。（备注：**从原摘要继承下来的术语也一并回正文查证**——正文无对应词时以正文术语为准，如"关键路径最早开始时间算法"→正文"确定性最早开工递推"，参照 M7）
- [ ] **C6** ▲ 无大段照抄题目原文；全部为自己转述。（✗ → 参照 M3）
- [ ] **C7** ○ 强调句/亮点句有 1~2 处（"本文的亮点/特色/创新性在于……"），且配证据。
- [ ] **C8** ◇ 人味化适度：开头可有情景化/背景描述，但方法句不抒情。
- [ ] **C9** ○ 错别字、标点、中英文混排（如 kW/m²、℃·s）规范统一。

## D. 数据与结果（D1~D7）

- [ ] **D1** ▲ 所有关键数值与正文**同源同值**，无矛盾。
- [ ] **D2** ▲ 数值单位标准统一（W/kW、cm/min、℃·s…），全文一致。（✗ → 参照 M6）
- [ ] **D3** ◇ 有效数字合理（一般 3~6 位），不在摘要中堆过长小数。
- [ ] **D4** ○ 结果句尽量给出"对比基准"（较传统××提升××% / 由上一基准压缩至……），增强说服力。
- [ ] **D5** ◇ 误差/拟合指标写法规范（R²、MRE、RMSE 等首次出现给全称或括注）。
- [ ] **D6** ▲ 摘要不放公式：模型公式一律文字点名（"推导了…反射率公式"），参数符号与数值用行内记号（R₀₁≈0.19、Qₘᵦ=0.35），公式/整式下沉正文（93 篇语料零公式，T1 强化）。（✗ → 参照模板 T1）
- [ ] **D7** ○ 灵敏度/鲁棒性结论有对应分析支撑，不与正文矛盾；**正文没有的分析不得虚构**（✗ → 参照 M14）。

## E. 格式与关键词（E1~E6）

- [ ] **E1** ○ 段落布局：总起段 1 段 + 逐题段 N 段 + 收束段（可选）+ 关键词 1 行。
- [ ] **E2** ▲ 篇幅 400~800 字（1~2 问 300~500，5 问可到 1000）；**高密度摘要**（每问都带数值+验证证据，如三问 ~1100 字）可放宽，**以信息密度为准，不为压字数删事实**。（✗ → 参照 M5）
- [ ] **E3** ▲ 关键词 4~6 个，与摘要/正文术语**逐字一致**，核心在前。（✗ → 参照 M11）
- [ ] **E4** ◇ "关键词："与"关键字："统一；分隔符全文一致——**新建模式统一用分号（；）**；**改写模式：原稿分隔符统一则保持原样**。
- [ ] **E5** ○ 问题编号写法（"针对问题一/问题1/对于问题一"）全篇统一；**子问统一为"问题一(1)(2)(3)"（小括号序号）**，不用"问题1.1/1.2"式。
- [ ] **E6** ○ 图表引用规范："见表 N/见附录 N/详见 result.xlsx"且表号真实存在。

## F. 与正文呼应（F1~F4）

- [ ] **F1** ○ 标题（若有）与摘要首句呼应，标题中的方法名在摘要中出现。（✗ → 参照 analysis.md §8.1）
- [ ] **F2** ▲ 摘要强调的重点，正文有足够篇幅支撑；正文最关键创新，摘要已点出。
- [ ] **F3** ▲ 摘要中引用的表号/附录/文件在正文确实存在且编号一致。
- [ ] **F4** ▲ 摘要无"待填/略/详见后文"等占位；无复制他人/往年摘要内容。（✗ → 参照 M13）

## G. 改写模式专用 · 事实保真（G1~G6，改写/评审既有摘要时必过）

- [ ] **G1** ▲ 改写后所有**数值与原稿/正文逐项一致**（数字、单位、换算均未变）。（✗ → 参照 M14）
- [ ] **G2** ▲ 未新增正文与摘要都没有的**结论或验证证据**；缺验证时用已有的等价证据替代（求解器 OPTIMAL、与基线对比、正文验证段）。（✗ → 参照 M14/M10）
- [ ] **G3** ▲ **模型名、表号、关键词**保持原样，未在改写中替换或篡改。
- [ ] **G4** ○ 原稿中的**关键事实无遗漏**（每问结果、创新点、结论判定都在新稿中出现）。
- [ ] **G5** ○ 篇幅未因改写失控（较原稿压缩或精简属正常，但不允许扩出合理区间）。
- [ ] **G6** ◇ 摘要区脚注/附注行（如"注：…使用 Matlab 写出并运行"）**保留原样**，属格式事实，改写它违反 G3。
- [ ] **G7** ▲ **算法/方法名的适用问号范围与正文逐问对应**：核验每个算法名"覆盖第几问"与正文一致（如"全程采用 CP-SAT"须确认问题一是否也用——若问题一为枚举/递推求解，则只能写"问题二至问题四采用 CP-SAT"），防止改写把局部方法放大到全文（M14）。

## 快速判分

**硬性门槛：全部 ▲ 项必须 ✔（23 项）**，任一 ✗ 即不合格，先修。

| 维度 | 通过项/总项 | 参考标准 |
|---|---|---|
| A 内容完整性 | /7 | ≥6 项 ✔ |
| B 逻辑链条 | /7 | ≥5 项 ✔ |
| C 语言表达 | /9 | ≥7 项 ✔ |
| D 数据与结果 | /7 | ≥6 项 ✔ |
| E 格式与关键词 | /6 | ≥5 项 ✔ |
| F 与正文呼应 | /4 | 全 ✔ |
| G 改写模式专用 | /7 | 全 ✔（改写任务） |

> 任何一项 ✗，优先参照 [mistakes.md](mistakes.md) 对应编号修正；修改后再跑一遍本清单。
